# AGENTS.md: Nature 3D Site
## Project
A scroll-driven 3D website about nature loss and recovery, with a grounded 
voice and text guide. Order: hero film, a 10-second animation of seven 
floating logos, then six sections (loss, underground, food, rivers, recovery, 
cities), then a footer with a contact form. Every factual claim shows its 
source.
## Stack
Frontend: Vite, React, TypeScript (strict), Tailwind, three, @react-
three/fiber, @react-three/drei, GSAP with ScrollTrigger, Lenis, Zustand. 
Backend: FastAPI, SQLAlchemy 2, Alembic, Postgres with pgvector. AI: 
Anthropic Claude API through the official SDK. Voice: STT and TTS behind 
adapter interfaces. Package manager: pnpm. Tests: Vitest and pytest.
## Sources of truth
- contracts/ defines shared types. Change it only with a note in PROGRESS.md.
- content/ and docs/blueprint.md hold all user-visible copy, facts and 
caveats.
- design/tokens.json holds visual decisions. Any value marked TODO(DIRECTOR) 
is undecided.
## Working method
1. Read the task card fully. Write a short plan: goal, files you will touch, 
risks.
2. Work on one component per branch, named cN-short-name, in small commits.
3. Run the card's Verify checklist. Attach evidence (command output, test 
names, screenshots) to PROGRESS.md.
4. If blocked or a decision is missing, stop and add the question to

## Hard rules (DO NOT)
1. DO NOT invent facts, numbers, copy or sources. Use only content/ and 
docs/blueprint.md. If something is missing, insert TODO(DIRECTOR) or 
TODO(RESEARCH).
2. DO NOT decide names, palette, fonts, 3D art style, narration or tone. Use 
design/tokens.json placeholders.
3. DO NOT reword caveats. Render them verbatim and visibly next to the claim 
they qualify.
4. DO NOT describe the 73% figure as animals dying. It is the average change 
in the size of monitored populations.
5. DO NOT write or imply that trees talk, send warnings or share resources 
through fungal networks. Say only what content/ says.
6. DO NOT put API keys or provider calls in the frontend. Keys live in 
environment variables; commit only .env.example.
7. DO NOT autoplay audio or request the microphone without a user click. 
Always show a visible indicator while the mic is live.
8. DO NOT store raw audio. DO NOT log transcripts unless 
LOG_TRANSCRIPTS=true.
9. DO NOT let a section specialist retrieve from other sections. Enforce the 
section filter on the server.
10. DO NOT add a dependency or asset without recording name, version, licence 
and reason in PROGRESS.md.
11. DO NOT edit another component's files, or change a contract, outside your 
task card.
12. DO NOT add features outside the task card.
13. DO NOT skip prefers-reduced-motion support.
14. DO NOT mark a task done without running its Verify checklist and 
attaching evidence.
## Definition of done
Build, typecheck, lint and tests pass. The Verify checklist is ticked with 
evidence. PROGRESS.md lists decisions, dependencies added and open questions.
Shared contracts
Parallel agents depend on these shapes. They live in contracts/ and nobody changes
them silently.

type SectionId = 'loss' | 'underground' | 'food' | 'rivers' | 'recovery' | 
'cities';
type SourceStatus = 'verified' | 'secondary' | 'pending';
interface SourceRecord {
  id: string; title: string; publisher: string; url: string;
  published: string; retrieved: string; licence: string;
  figure: string; caveat: string; status: SourceStatus; recheckBy: string;
}
interface Chunk { id: string; sourceId: string; section: SectionId | 'site'; 
text: string }
interface SiteState {
  progress: number;                               // 0 to 1, whole page
  activeSection: SectionId | 'intro' | 'footer';
  sectionProgress: Record<SectionId, number>;     // 0 to 1 each
  readSections: SectionId[];
  voice: 'idle' | 'listening' | 'thinking' | 'speaking';
  mode: 'guide' | 'specialist';
  specialist: SectionId | null;
}
// agent tools
search_docs({ query: string, section?: SectionId }) -> { chunks: Chunk[], 
sources: SourceRecord[] }
navigate_to({ section: SectionId })
start_brief({ section: SectionId })
hand_off({ section: SectionId })
return_to_guide({ summary: string })
// websocket messages
client -> server: audio_chunk | text | interrupt | context
server -> client: transcript_partial | transcript_final | reply_text_delta | 
reply_audio_chunk | navigate | sources | state | error

C7 Section scenes (six sub-tasks)
One agent per scene. Visual style is undecided, so use the placeholder palette from
design/tokens.json. Each scene must support a low-quality tier. Budget: 150 draw calls or
fewer and 2 MB of assets or less per scene (starting numbers, tune after measuring).
7a Loss: populations shown as clusters of instanced particles. Show the decline as
clusters shrinking on average, never as 73% of particles vanishing. Chips for
freshwater, land and ocean highlight their clusters using values from content.
7b Underground: a root and fungal network as line geometry with a pulse shader.
Clicking a node lights its connected edges. Labels say mycorrhizal fungi network,
nothing about trees communicating, warning or sharing.
7c Food: terrain tiles with a toggle between Today and Nature-friendly, morphing
between them. Use only figures from content. The Nature-friendly state is labelled
illustrative and carries no invented percentages.
7d Rivers: a shader river with a dam and a slider to remove it, plus fish particles. When
the slider reaches 100%, show the content caveat that recovery is not instant.
7e Recovery: a tiger silhouette made of particles, plus count-ups from content (India
2,967 to 3,682; global about 3,200 to about 5,700). Never imply the problem is solved.
7f Cities: a grey skyline that greens up, labelled illustrative. Its facts are
TODO(RESEARCH) until the director provides sources.
